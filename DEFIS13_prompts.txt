Prompts utilisés pour construire le projet DEFIS13
===================================================

Contexte global (à coller en premier)
-------------------------------------
Contexte du projet DEFIS13 :
- But : application Windows (exécutable via PyInstaller) affichant l'emploi du temps récupéré depuis Wigor.
- Auth : l'utilisateur colle MANUELLEMENT le header Cookie dans l'UI (pas d'auth automatique).
- L'API/endpoint renvoie du HTML (page d'emploi du temps). On doit parser le HTML pour extraire les cours.
- UI : Tkinter simple avec table (ttk.Treeview) affichant date, début, fin, matière, salle, professeur.
- Tests : pytest + pytest-cov, coverage > 80%.
- Architecture existante : app/{__init__.py, config.py, gui.py, index.py, main.py, models.py, wigor_api.py}
- Exemple de fragment HTML (fournir) et URL d'appel : https://ws-edt-cd.wigorservices.net/WebPsDyn.aspx
- Exemples de cookies fournis (DotNetCasClientAuth et ASP.NET_SessionId) — le client devra envoyer l'en-tête `Cookie: <valeur fournie>`.

________________________________________________

Prompt global (à utiliser pour demander la génération complète)
--------------------------------------------------------------
«Tu es un ingénieur logiciel senior. Génère l’arborescence et le code complet pour un projet Python nommé "DEFIS13" qui :
- Fournit une application GUI Windows (Tkinter) permettant à l’utilisateur de coller manuellement le header Cookie et de charger son emploi du temps depuis l’API Wigor (HTML).
- Parse le HTML renvoyé par l’API pour en extraire les cours.
- Sépare clairement la logique réseau (app/wigor_api.py), le parsing (app/index.py), le modèle (app/models.py), la config (app/config.py), la GUI (app/gui.py) et le point d’entrée (app/main.py).
- Inclut des tests Pytest (mocks), un fichier main.spec pour PyInstaller, et des fixtures d’exemple.
- Respecte PEP8, fournit des docstrings et du logging.
- Tout doit fonctionner sous Python 3.11+. »

Je veux que tu génères pour chaque fichier le code adapté selon les rôles suivants :

### 🔹 app/wigor_api.py
- Contient une classe `WigorClient` qui se connecte à l’API wigorservices.
- Utilise `requests` avec un header `Cookie` passé en paramètre.
- Fournit une méthode `get_schedule()` qui renvoie la réponse JSON formatée.
- Gère les erreurs (401, 404, 500) avec des exceptions personnalisées.

### 🔹 app/models.py
- Définit une dataclass `ScheduleItem` avec les champs : `date`, `start_time`, `end_time`, `subject`, `room`, `teacher`.
- Fournit une fonction `parse_schedule(json_data)` pour transformer la réponse API en liste de `ScheduleItem`.

### 🔹 app/gui.py
- Utilise `tkinter` ou `PySide6` pour créer une fenêtre "McGonagall Planner".
- La fenêtre contient :
  - une zone pour coller les cookies,
  - un bouton "Charger emploi du temps" → appelle `WigorClient.get_schedule()`,
  - une table affichant les cours (date, heure, matière, salle, prof),
  - une zone de logs/erreurs.
- Le code doit être bien organisé (classe `MainWindow`) et testable.

### 🔹 app/main.py
- Point d’entrée du programme.
- Instancie la fenêtre depuis `gui.py`.
- Charge les cookies si présents (optionnel).
- Lance l’application avec `if __name__ == "__main__":`.

### 🔹 app/config.py
- Contient les constantes (URL de l’API, paramètres).
- Exemple : `BASE_URL = "https://api.wigorservices.net/schedule"`

### 🔹 app/index.py
- Peut servir à des fonctions utilitaires : formatage, logs, regroupement par jour.

### 🔹 tests/test_api.py
- Mock `requests.get` pour tester les cas : succès (200), erreur 401, erreur 500.
- Vérifie que `get_schedule()` renvoie bien la liste d’objets `ScheduleItem`.

### 🔹 tests/test_models.py
- Teste `parse_schedule()` avec un JSON correct, un JSON incomplet, et un JSON vide.

### 🔹 tests/test_gui.py
- Teste que l’interface se crée sans erreur.
- Mock `WigorClient.get_schedule()` pour vérifier que le tableau se met à jour.

### 🔹 build/main.spec
- Fichier PyInstaller pour générer un exécutable Windows (`McGonagallPlanner.exe`).
- OneFile, avec icône et nom du programme.

5) Prompt pour app/index.py (parsing)
-------------------------------------
«Génère app/index.py avec la fonction parse_schedule_html(html: str, default_date: Optional[date]=None) -> List[ScheduleItem] :
- Utilise BeautifulSoup (bs4) pour parser.
- Hypothèse d’extrait HTML (inclus) :
  <tbody>
  <tr><td class="TCase" colspan="2"...>Election délégués</td></tr>
  <tr><td colspan="2" class="TCProf"...>serin emmanuelle<br>I2 EISI ALT ...</td></tr>
  <tr><td class="TChdeb">09:00 - 10:00</td><td class="TCSalle">Salle:T 206(THALIE)</td></tr>
  </tbody>
- Pour chaque <tbody> :
  - Extraire subject depuis le premier <tr> / première <td>.
  - Extraire teacher depuis la deuxième <tr> (texte avant <br>).
  - Extraire time depuis <td class="TChdeb"> et room depuis <td class="TCSalle"> (retirer le préfixe 'Salle:').
  - Normaliser les espaces et retours chariot.
  - Si la date n’est pas présente, utiliser default_date ou la date d’aujourd’hui.
  - Utiliser ScheduleItem.from_strings pour créer l’objet, et logger les erreurs sans planter le parsing global.
- Ajouter validations et lever ValueError si le HTML est totalement inattendu.
- Docstrings et type hints.»
